# Multiversal Interaction Operational Pilot Method

**Work item:** MV-CONT-005  
**Method version:** 1.0.0

## Purpose

The pilot tests whether the repository-installed owner–AI controls behave as intended under representative positive and negative scenarios. It is deterministic, privacy-preserving, repeatable in CI, and designed to detect regressions in continuity, completion evidence, correction intake, deliverable truth, capability reporting, source coverage, UI verification, notification deduplication, request alignment, owner reporting, and parallel-track preservation.

## Measurement boundary

The pilot measures executable repository controls and simulated mutations. It does not claim to measure every future model response, every product interface, or long-term owner-intervention reduction. Longitudinal results are marked **not yet measured** until evidence from later real work sessions is accumulated.

## Procedure

1. Load the 17 ordered scenarios from `PILOT_SCENARIOS.json`.
2. Run positive recovery and state-preservation scenarios in isolated temporary repository copies.
3. Attempt evidence-free completion and verify rejection without mutation.
4. Attempt prohibited correction intake, duplicate intake, and unapproved promotion.
5. Mutate each of the seven typed interaction receipts and verify rejection.
6. Verify effective coverage across 22 interaction patterns, eight known gaps, and 15 base evaluation cases, including MV-CONT-004 additive extensions.
7. Generate `OPERATIONAL_PILOT_SCORECARD.json` and its compact AIOC runtime projection.
8. Re-run the complete pilot during CI and require byte-equivalent semantic results apart from the preserved generation timestamp.

## Privacy

No raw private conversation text, titles, message excerpts, or attachment content is used. Correction tests use the existing synthetic minimized example. Source references remain opaque.

## Success gate

The pilot passes only when all 17 scenarios pass, all negative attempts are rejected or suppressed as designed, the runtime projection matches the source scorecard, the bootstrap reads the compact scorecard, and the Project Bible amendment is indexed.
