# SMB — CNI Interstitial Integration Amendment — 2026-09-09

**Status:** OWNER-APPROVED PLANNING AMENDMENT  
**Owner and final authority:** John Brandon Turner  
**Implementation authority:** none  
**Controls:** insert CNI-01..13 after SMB-07 and before SMB-08.

## Purpose

SMB-07 completes deep governed cross-system simulation. Before SMB-08 begins substantial first-party content production, Multiversal must have the modular content-pack and conditional-narrative interoperability layer needed to author that content against durable runtime contracts.

The SMB sequence is therefore amended at this boundary:

`SMB-01 → SMB-02 → SMB-03 → SMB-04 → SMB-05 → SMB-06 → SMB-07 → CNI-01..13 → SMB-08 → SMB-09 → SAA-01..20 → SMB-10 → SMB-11 → SMB-12 → SMB-13 → SMB-14 → SMB-15 → SMB-16 → BRP-01..11 → SMB-17 → SMB-18`

## SMB-07 handoff to CNI

SMB-07 must expose stable governed projections/events sufficient for CNI predicates and runtime bindings, including representative Character, Relationship/Reputation, Quest/Adventure, Scene/World, Inventory/capability and cross-system state. CNI may query those contracts but may not replace their owner-domain authority.

## CNI handoff to SMB-08

CNI-13 completion must leave SMB-08 with:

- stable pack/component manifests and identity;
- dependency/version/compatibility constraints;
- scoped narrative state;
- inspectable conditional predicates;
- structured dialogue bound to governed Actions/Events;
- Character-aware branching;
- NPC callback/continuity bindings;
- quest/scene/one-shot/re-entry triggers;
- cross-pack extension/conflict contracts;
- localization-key separation;
- dry-run/activation/rollback receipts;
- creator/developer inspection surfaces;
- a validated original Multiversal multi-pack golden proof.

SMB-08 then uses those contracts for first-party content libraries instead of inventing private pack/runtime semantics.

## SMB-08 amendment

SMB-08 — Core Content Production — must publish substantial first-party content through the completed CNI pack/component architecture where content is packageable. Its completion proof must include deterministic CNI manifest/dependency validation and must not rely on fixture-only or bespoke one-off loaders.

## SMB-09 amendment

SMB-09 — Complete First-Party Campaign — must use CNI conditional narrative/state/dialogue/continuity/trigger contracts for representative campaign flows. It remains a polished game-experience tranche, not a CNI reimplementation tranche.

## SMB-11 relationship

CNI package/runtime compatibility is not cross-user sharing authority. SMB-11 remains the owner of export/import, controlled sharing, dependency packaging across users/workspaces, forks/remixes and interchange safety. SMB-11 should consume CNI pack/component/version/compatibility manifests rather than define a second narrative-package format.

## SMB-16 relationship

CNI-10 guarantees that narrative/content strings are addressable through stable localization resources and that executable behavior is not inseparably embedded in one language. SMB-16 remains responsible for full supported-language UX, accessibility, locale/device validation and final localization completeness.

## Non-activation boundary

This amendment does not select or start SMB or CNI work, alter the current ARI family, create provider/external-service authority, authorize copyrighted source reuse, or permit public sharing/release. Runtime selection remains solely in the current pointer/index/checkpoint system.
