## Purpose

PCA turns the highest-value workflow lessons from the proprietary-capability survey into original Multiversal production tooling immediately before substantial first-party content production begins.

PCA does **not** clone commercial products. It builds Multiversal-specific authoring, procedural-generation, compilation, media-production, simulation, localization and QA tools over existing owner-domain contracts. It exists to reduce repeated manual work, recurring SaaS/model spend, AI-credit consumption and one-off asset generation while preserving provider independence and local/offline capability.

## Core doctrine

**Own the workflow; keep engines/providers replaceable.**

A PCA tool may use a commercial or open-source engine/provider through a lawful adapter, but Multiversal owns the recipe/manifest, semantic inputs, validation, provenance, outputs and fallback path wherever practical.

Every generated/imported media artifact registers through ARI. Every tool that consumes game/narrative truth consumes owner projections rather than maintaining a second canonical ledger.

## Upstream ownership boundaries

- **ARI:** resource identity, source/derivative lineage, bytes/reference state, rights/use capability, hashes, shared discovery.
- **SSA / World / Environment / Scene / MAI / ISE:** semantic spatial, map, environment and scene truth.
- **CAPP / Character / Species/Form / PAPT:** appearance/body truth and existing art-production contracts.
- **AAI:** audio asset, cue, soundscape and audio-event semantics.
- **DWC speech:** constructed-language pronunciation, exact-ID and acoustic-model authority.
- **CNI / CSW / Story / Adventure / Quest / Relationship:** narrative/content runtime and authored truth.
- **Action/Event/APM:** canonical mutation and automated-play authority.
- **MIB-15 / SMB-12:** AI-provider abstraction and approved live-provider integrations.
- **SMB-11:** creator sharing/interchange.
- **SMB-13 / BRP:** external testing/product-readiness operations.
- **SMB-16:** final product-wide localization/accessibility/device completion.

PCA may create production recipes, generated derivatives, authoring documents, candidate data, QA evidence and deterministic compilation outputs. It may not promote any of those to canonical truth except through the existing owning-domain path.

## Family execution rule

Each PCA tranche targets **24 active minutes or less under a healthy governed environment**, preserving normal closeout reserve. Oversized work is split before governed start. No PCA runtime preflight is created while ARI is active; PCA receives a sealed family preflight only when later selected.

## Tranches

### PCA-01 — Production Recipe Core, Clean-Room Provenance & Provider Adapter Contract

Create the common recipe/manifest model used by PCA: stable recipe IDs/versions, typed inputs/outputs, deterministic parameters/seeds, tool/provider identity, source hashes, licenses/rights, execution receipts, cache keys, local/provider execution modes, failure/retry semantics and ARI derivative registration. Encode PCM clean-room rules into validators so commercial inspiration never becomes an untracked code/content dependency.

### PCA-02 — Procedural Graph / Reusable Asset Recipe Engine

Implement a general DAG/node recipe layer for deterministic/repeatable production tasks. Support typed nodes, parameters, dependency scheduling, caching, invalidation, preview vs bake, batch variants, provenance, resource budgets and adapter-backed nodes. The engine must be useful without Houdini or any single DCC/provider.

### PCA-03 — Terrain, Ecology, Flora, Settlement & Spatial Generator Library

Build original generators that consume SSA/World/Environment/Scene semantics and output ARI-governed candidate resources: terrain fields/masks, erosion-style transforms, biome/ecology placement proposals, flora species/season/LOD variants, paths/roads, settlement/block layouts and reusable environmental variation. Suitability/procedural proposal is never silently canonical distribution or World truth.

### PCA-04 — Material, Texture, Bake & VFX Production Pipeline

Provide procedural material recipes, image-to-material preprocessing, tiling/map generation, texture baking, atlas/flipbook preparation, LOD-oriented derivatives, artifact detection and visual/technical QC. Commercial DCC/VFX tools may be optional adapters; PCA does not attempt to recreate a general sculpting/cloth/fluid package.

### PCA-05 — Character Asset, Rig, Garment Projection & LOD Production Pipeline

Consume CAPP/Character/Species/Form semantics to produce compatible character asset candidates, skeleton/anchor mappings, garment/equipment visual projections, facial/phoneme rig metadata, LOD/crowd derivatives and export manifests. Unsupported morphology remains explicit; the production tool cannot invent anatomy or Character state.

### PCA-06 — Motion & Facial Performance Factory

Provide video/mocap ingestion, skeleton normalization, retargeting, foot/root/hand locking, smoothing, loop/transition preparation, physics/balance/trajectory diagnostics, facial-performance alignment and standardized clip export. Preserve source-performance provenance and permit external capture/animation adapters without requiring them.

### PCA-07 — Interactive Audio Director & Authoring Workbench

Build authoring/profiling UX over AAI: event→cue mappings, variation pools, parameter/state-driven selection, ambience layers, adaptive music state graphs, mixing/snapshot intent, priority/virtualization policy, live simulation, deterministic preview and performance/loudness diagnostics. PCA does not replace the underlying audio renderer/DSP engine or AAI semantics.

### PCA-08 — Voice, Speech & Sound Production Factory

Provide local-first batch VO/speech workflows: governed character voice profiles, performance-transfer adapters, pronunciation dictionaries, DWC exact-pronunciation handoff, take/version management, normalization, segmentation, lip/facial timing metadata, sound-effect/ambience generation adapters, QC and ARI registration. Production voices may be temporary/proxy unless rights and human/perceptual gates say otherwise.

### PCA-09 — Style-Locked Asset Generation Orchestrator

Create provider-neutral generation jobs built from art-bible/style/reference manifests, deterministic briefs, negative constraints, seeds where supported, batch variants, review/retry, cost/credit budgets, local-vs-remote routing, caching and provenance. Generated assets remain candidates until owning workflows accept them. No provider may become canonical source authority.

### PCA-10 — Visual Narrative & Content Authoring Workbench

Provide graph/object authoring over CNI contracts: dialogue/quest/trigger flows, reusable content objects, condition/action binding, dependency visualization, validation/checkup, localization/VO context, preview/playtest and deterministic export. It must edit CNI-governed structured content rather than create a parallel narrative runtime.

### PCA-11 — Governed Character Intelligence Orchestrator

Implement the Multiversal-native equivalent of generic NPC-AI orchestration: permitted dynamic context assembly, grounded knowledge, scoped memory projections, speech/voice presentation, explainable prompt/context inspection, model/provider routing, structured tool/action proposals and strict Action/Event capability enforcement. AI never receives unrestricted NPC/GM authority; no-AI/fake-provider paths remain valid.

### PCA-12 — Systems Simulation & Balance Workbench

Provide deterministic/stochastic batch simulation for game-system parameters, resource flows, economies, encounters and cross-system scenarios using owner-domain rules. Support parameter sweeps, seeded Monte Carlo runs, sensitivity comparisons, target envelopes, regression baselines and exportable evidence. The workbench recommends/proves; it does not silently rebalance canonical rules.

### PCA-13 — Localization Production Workbench

Build production tooling between CNI-10 and SMB-16: translation memory, term/glossary enforcement, contextual metadata, screenshots/scene/speaker references, VO linkage, stale-string detection, review states, placeholders/format QA, import/export and provider-neutral MT/AI assistance. SMB-16 remains final localization/accessibility completion authority.

### PCA-14 — Autonomous Internal QA & Playtest Agents

Create internal developer/creator agents that can execute deterministic scenarios and bounded visual/interaction tasks, compare expected state/screens, collect logs/video/performance evidence, minimize/reproduce failures and emit bug bundles. This is not external tester recruitment and creates no SMB-13/BRP distribution authority.

### PCA-15 — Asset Production Governance, Locking, Dependency & Review Layer

Build an ARI-aware production overlay over existing VCS/storage: source-vs-generated distinction, large/binary asset status, advisory/exclusive locks where backend supports them, derivative/dependency impact, stale-build detection, review/approval state, task/owner linkage, batch provenance and cache/build visibility. Do **not** build another VCS; Git/LFS/P4/other lawful backends remain replaceable.

### PCA-16 — Golden Local-First Production Acceleration Proof

Prove the complete family on original Multiversal content: take semantic World/Character/CNI/AAI inputs through procedural environment/material/character derivatives, motion/voice/audio authoring, style-locked generation where used, localization prep, simulation/balance sweeps, asset-governance review and autonomous QA. Demonstrate deterministic receipts, ARI provenance/rights, cache reuse, provider-off fallback for every blocking workflow, and measured reduction in repeated manual/provider work.

5. SAA remains after SMB-09 and can consume PCA/ARI resources without being moved or duplicated.

Effective local segment:

`SMB-07 → CNI-01..13 → PCA-01..16 → SMB-08 → SMB-09 → SAA-01..20 → SMB-10`

## Cost-control requirements

PCA implementations must prefer, where practical:

- deterministic caches and content-addressed reuse;
- local execution on available workstation GPU/CPU for repeatable preprocessing/inference;
- batch operations over conversational one-at-a-time work;
- machine-readable recipes/manifests so lower-intelligence automation can safely execute mechanical tasks;
- provider abstraction, per-job cost/credit budgets and explicit fallback;
- artifact hashes and execution receipts so successful work is not regenerated merely because a conversation/runtime resets;
- incremental recomputation rather than full rebuilds.

## Proprietary-reference boundary

PCA derives requirements from PCM public-product study only. It authorizes no proprietary source/assets/model extraction, reverse engineering, trial-EULA violation or copied implementation. Direct third-party incorporation requires separate ARI rights/license review.
