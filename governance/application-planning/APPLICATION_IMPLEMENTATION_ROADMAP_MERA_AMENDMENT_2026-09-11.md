# Application Implementation Roadmap — MERA Amendment — 2026-09-11

**Status:** OWNER-APPROVED PLANNING AMENDMENT  
**Implementation authority:** none

## Decision

Insert **MERA — Multiversal Engineering, Refit & Assembly** as a 24-tranche future interstitial after MRCS and before MBES.

The affected future sequence becomes:

**MSAS-01..21 → MRCS-01..21 → MERA-01..24 → MBES-01..24 → SMB-08**

MERA does not change current work. ARI-16 remains selected_not_started with no implementation branch or implementation authority.

## Why MERA exists

Completed/implementation-ready Multiversal systems already own salvage, Item/Asset state, crafting/repair transactions, economy, vehicle/mecha/starship operations, Projects and Profession capability. The remaining gap is a coherent engineering/refit player+GM experience that composes those owners across ordinary equipment, machinery, vehicles, mecha and spacecraft without creating duplicate ledgers.

MERA's blocking representation is schematic/semantic rather than 3D-required. The resolution ladder is:

**Asset → system → assembly → subassembly → component → interface/connection → governed network**

Definitions may stop at any level; missing detail is not invented.

- SMB-08 remains after MBES-24.

## Authority preservation

LSS remains salvage/decomposition authority; PPIA-03/D17 remain Item/Asset state authority; MIB-12 remains repair/crafting transformation authority; MIB-13 remains economy authority; MIB-14/PPIA-04/F014 remain vehicle/mecha/starship definition/operation authority; APW/D26 remains Project/time authority; DPL/Profession remains work-capability authority; MRCS remains reusable rules/content authoring authority.

MERA adds orchestration, diagnosis, dry-run design, compatibility/refit planning, work sequencing, repair depth, tuning/calibration, engineering dependency visualization, test/acceptance and return-to-service workflows over those owners.

## Execution rule

Every MERA tranche targets no more than 24 active minutes. If a tranche cannot credibly fit, split it before start rather than weakening validation or overrunning the execution contract.
