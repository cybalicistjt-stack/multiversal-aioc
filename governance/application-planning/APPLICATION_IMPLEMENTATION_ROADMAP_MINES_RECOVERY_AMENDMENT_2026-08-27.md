## Purpose

The recovered handwritten/mine-note corpus contains several design concepts that are large and coherent enough to require roadmap families rather than being left as loose future notes. This amendment routes those concepts into explicit tranche programs while avoiding redundant programs where an existing owner already covers the recovered intent.

This amendment does **not** change the current runtime work item, branch, checkpoint, PR, implementation authority, release authority, migration reservation or deployment state. Runtime work selection remains controlled by the canonical bootstrap, authority registry, CURRENT_WORK_POINTER, selected checkpoint and live repository evidence.

Recovered material remains subject to the source/provenance rule: owner-direct notes and later owner decisions can authorize planning intent; assistant-generated historical expansion is not promoted merely by archive existence.

## Dependency-optimized forward order

The future dependency order becomes:

`AAI-10 → ISE-01..08 → SSA-01..10 → WCI-01..05 → KFR-01..08 → ODL-01..09 → SCL-01..11 → MAL-01..10 → ALP-01..08 → VTI-01..12 → SGC-01..08 → MIB-16 → MIB-17 → MIB-18 → SMB-01..16 → BRP-01..11 → SMB-17 → SMB-18`

Rationale:
- SSA consumes MAI/ISE and gives WCI richer governed spatial meaning.
- KFR consumes WCI knowledge views and supplies reusable familiarity before later command/crew/equipment proof.
- ODL supplies organization load/delegation semantics before SCL command-scale play.
- MAL waits for mature native Scene, GCL, MAI/AAI and strategic owner boundaries.
- ALP follows MAL so microgames can be an optional teaching modality, while ALP remains functional without MAL.
- VTI projects the richer native semantics outward only after those native owners exist.
- SGC remains the final source/product coverage closure and must include this amendment and all five new program outputs.

## Non-interference rule

This amendment is dependency planning only. It does not start SSA, KFR, ODL, MAL or ALP, and it does not interrupt or supersede the runtime-selected AAI work. Each new family receives implementation authority only through the normal governed selector when its dependency point is reached or the owner explicitly changes the critical path through governed planning.
