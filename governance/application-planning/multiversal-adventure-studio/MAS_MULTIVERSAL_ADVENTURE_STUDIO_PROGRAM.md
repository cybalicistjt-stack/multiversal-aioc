## Purpose

MAS is the creator-facing studio for turning Multiversal storycraft, maps, characters, creatures, quests, encounters, scenes, items and conditional content into complete playable Adventures, one-shots, episodes and multi-session arcs.

MAS does not replace CSW, CNI, Story, Adventure, Scene, Session, Quest, World, Character, Encounter or Action/Event authority. It binds and packages those owners through explicit references and proposals.

Governing direction:

`creative plan → governed Adventure draft → owner-domain bindings → validated playable package → session projection`

Prepared content is never treated as proof that an event occurred. Live state remains owned by the runtime domains.

## Placement

`SMB-07 → CNI-01..13 → PCA-01..16 → MCS-01..21 → MCCS-01..21 → MAS-01..21 → SMB-08 → SMB-09 → SAA-01..20 → SMB-10`

CNI supplies conditional content and package runtime foundations. PCA supplies generic authoring, simulation and review tools. MCS supplies maps. MCCS supplies entity presentation. CSW supplies creative planning, Story Bible, nonlinear design, continuity and writing contracts. MAS integrates those foundations into the finished Adventure-authoring and session-preparation surface before first-party content production.

## Core doctrine

- One versioned Adventure studio supports outline, board, graph, timeline, map/location, cast, encounter, clue, session-prep and package projections.
- Reusable prepared definitions remain distinct from live run state.
- Existing Multiversal objects are referenced rather than silently duplicated.
- A prepared scene, clue, encounter, reward or timed event is not an occurrence.
- Linear, branching, node-based, sandbox and hybrid structures are all valid.
- Optional AI may suggest or draft, but cannot silently incorporate, publish or mutate live state.

## Benchmark and clean-room rule

MAS benchmarks public capability/workflow documentation from Foundry VTT, World Anvil, LegendKeeper, Alchemy RPG, Quest Portal, articy:draft, Arcweave, ink and Yarn Spinner. `MAS_BENCHMARK_CAPABILITY_MATRIX.md` records the details.

The benchmark is clean-room only. MAS may learn capability requirements and workflow outcomes, but it does not copy proprietary source, protected content/assets, sample Adventures, distinctive UI expression, private protocols or vendor-specific implementation details.

## Cross-cutting requirements

Every tranche preserves stable identity, history/recovery, privacy-aware projections, nonvisual/keyboard alternatives, local-first blocking workflows where practical, ARI/D29 provenance, deterministic receipts where determinism is claimed, explicit unsupported states, and the boundary between creative draft, prepared definition, binding proposal, published package and live run state.

## Golden proof

MAS-21 proves original Multiversal examples covering a one-shot, branching investigation, site expedition, sandbox structure, social-focused Adventure, episodic arc and multi-session package. The proof must include CSW handoff, MCS map binding, MCCS cast presentation, CNI conditional content, quest/encounter/item references, visibility controls, session prep, branch replay/reset, stale-reference diagnostics, structured packaging and prepared-content-versus-live-state separation.

## Non-goals

MAS does not become a second narrative runtime, map editor, character editor or live play engine. It does not force one story structure, treat simulation as live truth, require a paid/cloud Adventure-authoring provider, or authorize public marketplace distribution, paid credentials, tester access or release/deployment.

## Family execution rule

When MAS is eventually selected, it receives its own sealed family preflight. Every execution unit targets 24 active minutes or less under a healthy governed environment with protected closeout reserve; oversized units split before governed start.

No MAS implementation authority exists now.

## Completion standard

MAS completes only when all 21 tranches are `completed_verified`, the golden proof demonstrates multiple Adventure structures without a golden-path assumption, normal authoring works without a paid/cloud provider, CSW/CNI/MCS/MCCS bindings preserve owner authority and hidden information, and SMB-08/09 can produce first-party Adventures and long-form play without inventing a parallel authoring system.
