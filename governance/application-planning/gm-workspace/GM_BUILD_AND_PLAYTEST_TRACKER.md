# Multiversal GM build and playtest tracker

**Planning baseline · November 19, 2026**

Build a complete evening of play in small steps. Start with a GM who can create a campaign, accept a character from the player builder, prepare a scene and a basic encounter, and run that scene from the GM screen. Use the same campaign to test noncombat, save and resume, shared assets, and vehicle play. Then expand what the GM can author and share.

## Starting point

- **OPS5.** The audited AIOC main is `df6e2b86`, state revision 665. PCV-03F is still in progress. The inspected app main is `db8e2d9b`. The PCV-03F candidate in [Multiversal-app PR #840](https://github.com/cybalicistjt-stack/Multiversal-app/pull/840) is `70b3028e`. The candidate exposes more of the account, invite and connection flow than main. A visible connection flow does not certify installed play.
- **What to reuse.** The normal product shell has local campaign, world and character foundations, an indexed Library, and a Sessions workspace. A5 scene prep, A6 action decisions, A7 combat, A8 assets and transport, A9 investigation/social, MTLC table tools, and creator workbenches already cover substantial parts of the remit. The reviewed normal shell and candidate do not establish the full GM prep → shared session → outcome loop. The draft CQR2 review corroborates specific route and authority gaps.
- **Character-builder precedent.** Reuse its source-linked inventory, named steps, repeatable playtest and defect log. This tracker distinguishes existing source evidence from the actual playtest result. The player handoff begins with an explicitly finished or submitted character and uses the governed character record through play. It keeps drafts recoverable, species choices explicit, gear and operational assets in credits, and skill ranks separate from weapon, armor, vehicle and technology proficiency.
- **Scope.** This is a proposed delivery order, with no product tranche selected by this document. Minimum prep for a live scene belongs beside PCV-04. Full GM and creator authoring belongs in PCV-07. MTLC remains the owner of group coordination and continuity. Confirm strict PCV predecessor and operational selection in OPS5 before each implementation tranche. The existing Multiversal product model uses Theater of the Mind and bounded zones. Full VTT work is outside this plan.

## Shared checks

- **Draft and live state.** A GM can save a draft, leave and recover. Launch uses a validated prepared version. A template, a campaign placement and the live instance keep distinct identities. Fixes and later revisions preserve the history of a scene already played.
- **Search and paging.** Long pickers use the character-builder rule: First, Previous, Next and Last at both ends. Navigation returns the user to the top of the list and preserves search/filter context. A rejected or restricted result explains the permitted next step without revealing protected content.
- **Ownership and accounting.** The completed player sheet, GM screen, economy and vehicle controller use their existing governed records. Verify credit vs XP balances, skill vs proficiency, actor and station permissions, and original vs amended outcomes. Repeating a request must settle it once.
- **Visibility.** Test GM, invited player, other player and removed player. Use a synthetic secret with a unique marker. Inspect the player views and secondary surfaces affected by the change, including history, search, recents, notifications, exports, caches and diagnostics. Preview as Player uses the same audience rules as the authentic player view.
- **Recovery.** Reopen after normal close, force-stop, connection loss and rejoin at the boundaries the tranche touches. Compare the saved record or authoritative event history with rendered GM/player state. Verify reconnect starts from the correct sequence and leaves drafts and live state intact.
- **Required context.** The first slice is desktop-oriented and can be exercised locally. Installed parity and real shared authority are tested separately on Windows and Android when the relevant governed gate is reached. Track application build/commit, test environment and real boundary evidence for the result claimed.
