# ENV-14 — Ability, Adaptation & Environment Creator Composition Contract

**Program:** ENV — Environment Preset & Overlay  
**Tranche:** ENV-14 — Ability, Adaptation, Creator & Full-Library Reconciliation  
**Authority:** content/design/provenance only; no application implementation authority.

## Purpose

ENV-14 reconciles environment composition with retained environment-linked abilities without turning environmental resemblance into new canon. The governing rule is: **exact source relationship outranks environmental similarity**.

The creator works with the already-governed 76 presets, 19 archetypes and 47 overlays. It does not become a new source of creature, ability, spell, item, vehicle, World/Reality/Place or runtime truth.

## Relationship authority classes

Environment-linked ability information must remain visibly separated into four classes:

1. **Canonical source link** — one of the 68 exact `ENVIRONMENT_ABILITY_LINKS_v1.0.0.csv` relationships. These links remain unchanged.
2. **source-supported but not canonically promoted** — the ability source contains an exact environment-specific collection/member relationship, but the environment promotion package did not create a canonical Environment->Ability link. The relationship may be shown as source evidence or a reconciliation candidate, never relabeled as canonical by ENV-14.
3. **Shared multi-environment source collection** — `Special Perks (Applicable to Multiple Environments) remain ability-system-owned`. Their own source wording controls applicability; ENV does not attach the collection to every preset that looks relevant.
4. **Context seam only** — `Chaos/Foam Influence is a context seam, not an ability bundle`. Activating `OVL-SUP-CHAOS-FOAM` may satisfy an environment-context predicate for a separately owned ability, but it neither grants nor copies that ability.

No relationship class may be silently upgraded by a creator, preset conversion, archetype inheritance, overlay application or ecological/property match.

## Ability acquisition and evaluation

Selecting or composing an environment **must never auto-grant an ability**. Acquisition, XP cost, prerequisites, usage limits, saves, damage, bonuses, conditions and other mechanics remain owned by the ability/participant systems.

Where an ability's own source explicitly names an environmental property or context, the ability system may evaluate that requirement against the derived environment result. `Resolved Environment remains derived and read-only`; it is input to evaluation, not a new authored identity.

A source statement such as toxic gas, airborne hazard, deep darkness, difficult current, Chaos/Foam presence or a named environment can therefore be tested against the resolved context when the owning system has an explicit mapping. ENV-14 does not generalize the statement beyond what the source supports.

## No similarity-to-authority conversion

The creator **must never manufacture a canonical link from archetype, overlay, Habitat Signature, or property similarity**.

Examples:

- River / Stream and Swamps may both be wet, but River / Stream does not inherit `Swamp Perks`.
- Rocky Desert and Sandy Desert may share heat/aridity conditions, but Rocky Desert does not inherit `Sandy Desert Perks`.
- Tundra and Arctic Tundra and Taiga may overlap in cold/open-country properties, but the newer Tundra preset does not inherit the old source tree unless a later source/owner relationship explicitly establishes it.
- Radiation overlay does not grant or attach abilities from Post-Apocalyptic Radioactive Zone.
- Dimensional Bleed, Portal Activity or Temporal Instability do not inherit Chaos/Foam perks merely because some source phenomena overlap.

This protects the 36 post-ENV-05 expansion presets from accidental source-link cloning.

## Creator projection behavior

A future `custom environment creator` or GM environment workbench may project ability relationships alongside a composed environment, but each projected relationship must include:

- relationship authority class;
- source collection/record identity where available;
- canonical Environment->Ability link identity when one exists;
- source environment/preset or context seam that caused the projection;
- an explicit statement that selection is not acquisition;
- unresolved/source-supported state when canonical link authority does not exist.

`source provenance must be visible in every ability suggestion`.

The creator may start from a preset, add overlays and local parameters, and inspect a derived resolved environment. It must not duplicate archetype rule bodies, mutate source profiles, rewrite source ability mechanics, or promote its own similarity judgment into canon.

## Chaos/Foam reconciliation

The retained `Chaos and Foam Environment Perk Tree` contains eight member perks whose source explicitly conditions them on the Chaos or Foam. ENV-13 already established `OVL-SUP-CHAOS-FOAM` as the reusable environmental context seam.

ENV-14 binds only that context predicate. XP costs, prerequisites, damage, saves, navigation effects, daily uses, mutation/exposure rules, time ratios and every other source-specific mechanic remain with the ability/source authorities. Activating the overlay never automatically grants any of the eight perks.

## Shared special-perk reconciliation

`Special Perks (Applicable to Multiple Environments)` contains five member perks. The title and member text are source authority that applicability is broader than one named preset. ENV-14 preserves the collection as shared ability-system evidence rather than manufacturing five links to every underground, toxic, dark or ruined environment.

If a member's own text explicitly names a property, the ability system may later evaluate that predicate against Resolved Environment. That evaluation is not a new Environment->Ability identity link.

## Full-library boundaries

- ENV-14 adds no presets, archetypes or overlays.
- ENV-14 adds, removes or rewrites zero canonical Environment->Ability links.
- ENV-15 owns Habitat Signature vocabulary and ecological matching semantics.
- ENV-16 owns the environment-to-creature discovery projection contract.
- CEW owns creature ecology and distribution.
- Ability acquisition and participant effects remain externally owned.
- Application/runtime implementation remains separately governed.
