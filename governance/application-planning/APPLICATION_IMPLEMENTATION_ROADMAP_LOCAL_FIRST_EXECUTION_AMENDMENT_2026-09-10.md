## Required tranche-start evaluation

Before implementing commodity mechanics, each future selected tranche must classify relevant work against the Local-First Execution Overlay:

1. deterministic installed tool;
2. approved reusable/open library;
3. local model/agent;
4. local specialist engine;
5. hosted commodity provider;
6. frontier reasoning;
7. human/owner judgment.

This is an execution-routing decision inside the selected tranche, not a new program or authority lane.

## High-value effects on current future work

- **ARI:** use mature archive/media/metadata/search tools as independent workers/oracles while Multiversal retains staging, safety, identity, rights, recovery and catalog semantics.
- **MIB-16/18:** consume local diagnostics, graphing, retrieval, security and benchmarking evidence instead of building commodity tooling from scratch.
- **SMB-03..07:** use DuckDB/Graphviz/Gephi/QGIS/Blender and deterministic scripts for simulation, graph, spatial and production evidence where appropriate.
- **CNI:** preserve the Multiversal-native narrative/state runtime; use graph/layout/validation tooling for authoring and inspection rather than inventing generic layout engines.
- **PCA:** treat installed media/AI/DCC/GIS workers as replaceable execution engines. PCA owns recipes, manifests, orchestration, provenance, validation, caching and product UX.
- **SMB-08/09:** prefer governed open-content sources, local production recipes and reusable derivatives before repeated one-off paid generation.
- **SAA:** use existing image/vector/composition engines where practical; SAA owns project state, composition semantics, rights filtering, accessibility and product workflow.
- **SMB-12:** first real-provider acceptance is amended to a local provider through MIB-15 before paid-hosted AI becomes necessary; see the SMB-12 local-provider-first amendment.
- **SMB-13..16 / BRP / SMB-18:** automate evidence, security, backup, diagnostics and regression work with installed tools while preserving real-user, network, accessibility, privacy and operational acceptance requirements.

## Non-reimplementation guidance

Future tranches should not create general-purpose substitutes for archive codecs, media codecs, OCR, vector databases, embedding runtimes, generic TTS/STT, image-generation runtimes, DCC/CAD/GIS applications, graph layout, backup systems or security scanners unless tranche-specific evidence proves that an adapter cannot satisfy the required product behavior.

This guidance does not prevent Multiversal from implementing its own portable fallback when distribution, license, security, offline, platform or deterministic requirements genuinely require one.
