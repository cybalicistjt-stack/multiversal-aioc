## Reconciliation rules

1. The registry's `designStatus` is **design maturity only**, not implemented source, deployed functionality, or alpha readiness. Preserve the registry's 9 `implementation-ready` and 16 `registered` values; don't falsely upgrade or downgrade those fields because of later PRs.
2. A **merged PR** and a verified live source path demonstrate that a **bounded source slice is on application main**, not that the full feature definition, real-device behavior, end-user deployment, or release gate is satisfied.
3. **Open PRs** are unmerged and cannot certify deployed/merged feature status. Superseded PRs are not acceptance evidence.
4. Old packet indexes saying **"implementation not started"** are historical design handoffs and are stale when interpreted as current application implementation truth. Their packet-readiness classifications may still be valid.
5. Source paths in the table were checked against application `main`. Repeated paths reflect different feature slices sharing an implementation, not independent proof of each complete feature.
6. This is a source/PR crosswalk, **not an exhaustive contract-to-test acceptance matrix**. A precise fully-complete feature claim still requires its owned test, security, privacy, data, and supported-platform gates.
