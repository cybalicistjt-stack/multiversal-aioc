## Purpose

Supplement the broad proprietary production-tool survey with a smaller set of mature game/product workflows that expose useful Multiversal-specific product lessons. This supplement does not duplicate completed VTI work and does not authorize direct copying of proprietary code, assets, content, file formats, private protocols or protected expression.

### PCM-GP01 — Dungeon Alchemist — `STUDY_PATTERNS` / PCA-03 + MAI/SSA

High-level room/environment intent can produce an immediately editable map while structural metadata such as walls and lighting can travel with the export. Multiversal should preserve the same useful property: semantic/procedural assistance produces editable governed geometry, not a flattened opaque image.

Public reference: https://www.dungeonalchemist.com/

### PCM-GP02 — RPG Maker MZ — `STUDY_PATTERNS` / PCA-10 + CNI

Decades-refined no-code event authoring demonstrates the value of database-backed objects, switches/variables, conditionals, reusable common events, event commands, playtest controls and searchable references. Multiversal's equivalent must compile to typed CNI/Action/Event contracts rather than inventing a parallel mutation engine.

Public reference: https://www.rpgmakerweb.com/products/rpg-maker-mz

### PCM-GP03 — D&D Beyond — `STUDY_PATTERNS` / WCI + ISE + Character/Campaign

The useful lesson is product continuity: one Character projection flows through builder, sheet, campaign, map/encounter and shared game-log surfaces with contextual content/rules help. Multiversal should achieve that continuity while retaining its own owner-domain truth and without using D&D rules/content/art.

Public reference: https://www.dndbeyond.com/

### PCM-GP04 — World Anvil / LegendKeeper — `STUDY_PATTERNS` / WCI + World + CNI

Interlinked world knowledge, templates, atlas/map linking, timelines/calendars, secrets/permissions, search, collaboration and lightweight boards demonstrate how large setting knowledge can remain navigable. Multiversal should project canonical World/Campaign knowledge into these affordances rather than create a separate wiki authority.

Public references: https://www.worldanvil.com/ and https://www.legendkeeper.com/

### PCM-GP05 — Arkenforge Master's Toolkit — `BUILD_MULTIVERSAL_NATIVE` subset / ISE + MAI + AAI

Local/offline tabletop operation, separate GM/player presentation, fog/lighting, broad media import and map-linked soundscapes are particularly aligned with Multiversal's local-first tabletop objective. Native work should combine existing MAI/AAI/ISE authorities rather than create another scene/audio truth store.

Public reference: https://arkenforge.com/

### PCM-GP06 — TaleSpire — `STUDY_PATTERNS` / ISE + Scene + future P3D

Building and playing in the same persistent synchronized space, reusable scene chunks, multiple-GM operation, live edits, measurement and cinematic presentation are useful references for future spatial presentation. Any 3D representation remains a renderer over governed Scene/World truth.

Public reference: https://talespire.com/

### PCM-GP07 — Hero Forge — `STUDY_PATTERNS` / PCA-05 + P3D/CAPP

Parametric assembly, modular parts, slots/anchors, scaling/positioning, kitbashing, pose and printability demonstrate a highly effective user-facing composition model. Multiversal's native implementation should derive from Character/species/form/equipment truth and emit renderer/print derivatives through ARI.

Public reference: https://www.heroforge.com/

### PCM-GP08 — BrowserStack Percy — `BUILD_MULTIVERSAL_NATIVE` local subset / PCA-14 + SMB-16

Cross-browser/platform screenshot baselines, visual diffs and responsive review can be reproduced for owned environments using Playwright-based local infrastructure. External device farms remain sensible only for real devices/OS combinations we cannot economically own.

Public reference: https://www.browserstack.com/percy

### PCM-GP09 — Sentry product workflow — `BUILD_MULTIVERSAL_NATIVE` subset / MIB-16 + PCA-14 + BRP

Error fingerprints, breadcrumbs, traces, release/build identity and privacy-controlled replay reduce expensive diagnosis from sparse logs. Multiversal should produce deterministic privacy-minimized diagnostic bundles first; optional AI may interpret those bundles but should not be the evidence source.

Public reference: https://sentry.io/

### PCM-GP10 — Live2D Cubism-class parametric 2D puppetry — `STUDY_PATTERNS` / PCA-05 + SAA

Parameterized deformation, expressions, motion and simple secondary physics show how a bounded authored 2D asset set can support many presentations. A native Multiversal representation should use original/open implementation components and Multiversal-owned parameter semantics, not proprietary Cubism formats or editor behavior.

Public reference: https://www.live2d.com/en/cubism/

## Foundry disposition

Foundry Virtual Tabletop is intentionally not added as a new PCM target here. Multiversal already completed a dedicated provider-neutral VTI program including a deep Foundry integration and ISE explicitly targets Foundry-level spatial capability. New Foundry study should occur only when a current owning tranche identifies a concrete unfilled gap.

## Implementation rule

These references may refine existing PCA/CNI/ISE/WCI/P3D acceptance criteria when their owning future tranche is planned or started. They do not add a second production-acceleration family and do not alter the current ARI pointer.
