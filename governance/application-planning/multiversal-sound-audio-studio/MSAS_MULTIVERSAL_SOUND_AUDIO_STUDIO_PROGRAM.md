## Purpose

MSAS is the creator-facing studio for producing, editing, composing, mixing, directing, previewing and binding Multiversal music, ambience, sound effects, voice and adaptive audio without creating a second audio-runtime or gameplay-state authority.

The governing semantic direction is:

`World / Environment / Scene / Adventure / Combat / Dialogue / Event projections → AAI cue and soundscape semantics → MSAS authored audio assets/behaviors → runtime audio renderer`

The production direction is:

`lawful source recordings / MIDI / samples / generated candidates → edit / compose / sound-design / mix → AAI semantic binding → validated runtime profile`

A prepared cue, state mapping, playlist, score transition or soundboard trigger never proves that the corresponding gameplay event occurred.

PCA supplies reusable production/audio tooling, AAI supplies completed provider-neutral audio semantics and runtime interoperability, DWC speech supplies constructed-language pronunciation/acoustic authority, MCS/MCCS/MAS supply places/entities/adventures to bind, and MSAS supplies the finished creator-facing audio-production and adaptive-direction experience before first-party content production.

## Authority boundaries

- **AAI** remains authoritative for audio assets, semantic intents, cues, soundscapes, provider capability/availability, event bindings and playback/interoperability semantics.
- **DWC speech** remains authoritative for constructed-language pronunciation, exact IDs and governed acoustic/pronunciation models.
- **ARI** owns audio resource identity, bytes/reference state, hashes, rights/use capability and derivative lineage.
- **World / Environment / Scene / Adventure / Combat / Dialogue / Action/Event** retain their own canonical state and event authority.
- **PCA-07/08** supply reusable authoring/production primitives; MSAS productizes those capabilities into a coherent user-facing studio.
- MSAS does not become a general replacement for REAPER, Ableton Live, Wwise, FMOD, QLab or a specialist mastering suite.
- Commodity DSP, codecs, plugin hosting and media transforms should use lawful mature replaceable libraries/tools where practical.

## Core product doctrine

1. Local-first/offline blocking workflows must remain usable without a paid audio, music or voice provider.
2. Semantic audio intent stays distinct from individual files, providers and generated derivatives.
3. Multiversal state may drive adaptive music, ambience and cues, but audio cannot grant or infer gameplay truth.
4. Creator-facing audio supports both timeline/multitrack production and state/event-driven adaptive structures.
5. Soundscape authoring treats ambience as layered, variable systems rather than requiring flattened loops.
6. Voice production keeps speaker identity, consent, language, pronunciation, takes and usage rights explicit.
7. Generated music/SFX/voice are candidates until explicitly accepted and registered; optional generation never silently publishes or binds content.
8. Accessibility includes transcripts/captions for speech and non-audio descriptions for meaningful sonic cues, plus safe loudness/metering behavior.
9. Unsupported imports, middleware features or round-trip semantics remain explicit; MSAS never fabricates missing behavior.

- world/region/location ambience with weather/ecology layers;
- exploration music with adaptive horizontal/vertical transitions;
- combat intensity states and stingers;
- dialogue VO with take/version handling, localization and DWC pronunciation binding;
- spatial emitters/zones with listener preview;
- a live GM soundboard/cue-stack projection;
- multistem editing/mixing/master validation with loudness evidence;
- captions/transcripts and semantic non-audio descriptions for meaningful cues;
- local-first operation with optional generators/providers disabled;
- ARI rights/provenance and derivative lineage for every source/output;
- deterministic state/event simulation receipts where determinism is claimed;
- a structured bridge/round-trip case with explicit unsupported/loss reporting;
- explicit proof that prepared cue mappings do not become runtime event truth.
