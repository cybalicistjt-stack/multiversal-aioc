UI/UX Consultancy Phase

Professional owner-centered refinement before final AIOC hardening

Project ControlSemantic Recovery

Timeline placement

Semantic recovery quality gate → UI/UX consultancy → large-scale owner review → final hardening and release validation.

This phase begins after semantic recovery is trustworthy enough to provide realistic data and before thousands of owner decisions are processed through the interface.

Consultant objective

Redesign the AIOC around the owner's real jobs: resume work, understand true status, review recovered content, resolve relationships and blockers, approve canon, inspect provenance, manage releases, and recover from failures.

Ten-stage process

  1. Discovery: inventory modules, workflows, pain points, repeated actions, risks, and terminology.
  2. Information architecture: consolidate modules into stable goal-oriented workspaces.
  3. Interaction and state model: standardize statuses, drafts, approvals, loading, errors, saving, resume behavior, and rollback.
  4. AI-assisted work design: expose recommendations, confidence, evidence, uncertainty, consequences, and reversible actions.
  5. Game-development review: validate support for rules, objects, packs, dependencies, balance, provenance, and relationships.
  6. Low-fidelity prototypes: compare multiple navigation and workspace models with real Multiversal tasks.
  7. Owner usability testing: measure wrong turns, time, clicks, confidence, and ability to resume work.
  8. Visual and accessibility system: strengthen hierarchy, contrast, keyboard use, responsive dense-data layouts, and status clarity.
  9. High-fidelity implementation: migrate all functions through shared components without losing tools.
  10. Validation: prove no orphaned module, ambiguous completion state, lost progress, unsafe action, or inaccessible core workflow remains.

Owner-centered rules

  • Minimize repeated prompts, manual file movement, and GitHub troubleshooting.
  • Make the next useful action obvious while retaining expert detail on demand.
  • Preserve work position, filters, decisions, and context across sessions.
  • Keep provenance next to every important decision.
  • Separate machine complete, needs review, owner approved, and canonically complete.
  • Never silently merge, approve, or rewrite canon.
  • Favor coherent batches and bulk review with preview, exceptions, and undo.

Planned shared components

Return-to-work panel · task and batch lists · source-evidence viewer · candidate comparison · relationship resolver · status timeline · persistent filters · bulk review tray · decision ledger · diagnostics and recovery.

Success measures

Resume time, status comprehension, clicks per decision, provenance visibility, accidental reversals, batch completion, GitHub dependency, and owner confidence.
